# RelayScope 产品规格

[English](product-spec.md) | **中文**

## 目的

RelayScope 为 AI API 中转站的用户回答两个实际问题：

1. 如果我现在想用某个模型，当前哪个站点和分组看起来可用？
2. 如果我现在想用某个站点，当前哪些被监控的模型和分组看起来可用？

它报告各站点或其探针公布的数据。它不会调用模型，也绝不能让人误以为它独立核实过模型服务。

## 产品优先级

按降序排列：

1. 清晰、可筛选、实时的数据。
2. 在 1 核、768 MB 服务器上的低资源占用。
3. 无人值守下的稳定运行。
4. 低投入的站点与匹配维护。
5. 简单的代码与运维。

跨站点统计评分、长期分析和低用量模型覆盖率不是目标。

## 公开体验

- 仅中文的响应式界面，适配桌面与移动端。
- 按监控模型、提供商、站点、原始模型名和站点分组浏览。
- 完整保留并展示来源模型名与分组名的原文。
- 展示来源 URL、来源时间戳、采集时间戳、可用的样本数以及采集新鲜度。
- 区分服务健康与采集健康。
- 排序依据：服务状态、新鲜度、来源成功率、样本量、延迟。不发明综合评分。
- 空采样窗口一律视为 `no_samples`（无样本），绝不视为健康或失败。
- 无需整页刷新即可增量更新。

## 管理体验

- 带密码保护的管理后台，登录有速率限制。
- 管理站点、适配器选择、调度计划、适配器配置和启用状态。
- 管理热门模型匹配规则，并可立即对已发现的原始名称预览匹配结果。
- 检查歧义匹配、疑似热门却未匹配的名称、采集运行、登录状态、人机验证挑战状态和数据过期情况。
- 手动触发一次有边界的采集或会话恢复运行。
- 绝不显示完整 Cookie、OAuth 状态、加密密钥或其他凭据。

## 添加站点

RelayScope 以空数据库启动。站点通过管理后台添加。展示名可能退回为站点自身标题或主机名，创建后可以编辑。配置格式参见仓库根目录的 `sites.example.json`。

## 模型匹配规则

RelayScope 自带一小组示例匹配规则，演示各种匹配能力（必选词、排除词、正则模式、别名、基于优先级的特异性）。管理员通过后台添加自己的规则，以匹配自己关心的模型家族。

匹配策略刻意偏向召回。前缀与后缀变体作为不同的原始模型并存。规则是确定性的且可编辑。恰好一条匹配规则负责指定公开的规范模型；出现多个匹配候选时保留为管理员可见的冲突，在规则集修正之前不做公开的规范指定。原始名称的精确写法永远不会被改写。

## 采集与展示默认值

- 健康站点每 15 分钟采集一次，附带有边界的抖动。
- 最近一次获取失败、需要登录或未能通过人机验证挑战的站点每 30 分钟重试一次。采集成功后自动恢复正常间隔。
- 紧凑列表由当前快照驱动，但其服务状态来自最新的真实来源时间桶；来源提供的 24 小时汇总只作为聚合指标使用。
- 最新来源时间桶超过两小时即视为 `no_samples`，即使采集本身是新鲜的。公开时间线绝不会用聚合值或采集时间合成一个槽位。
- 当来源省略时间桶结束时间时，推断出的覆盖范围上限为一小时。
- 历史时间桶最多保留 72 小时，之后清理。
- 成功率达到或超过 85% 为 healthy；50% 至不足 85% 为 degraded；低于 50% 为 failed。缺失样本仍为 `no_samples`。
- 只有当来源提供了新鲜的、权威的 24 小时历史窗口，且该模型成熟到足以判断时，卡片才会在连续 24 小时无样本后被隐藏。仅报告存在性或当前健康的来源始终保持可见；被隐藏的卡片保留在存储中，一旦有新样本立即重新显示。

## 状态语义

服务状态与采集状态相互独立。

服务状态：

- `healthy`
- `degraded`
- `failed`
- `no_samples`
- `removed`
- `unknown`

采集状态：

- `fresh`
- `stale`
- `collecting`
- `collection_failed`
- `login_expired`
- `challenge_pending`
- `challenge_failed`

采集失败时保留最近一次成功的服务快照。只有连续三次成功的完整目录采集都未包含某个原始模型，它才会变为 removed。removed 条目三天后从常规视图中隐藏，但作为轻量的身份元数据继续保留。

## 认证与人机验证边界

- 已认证的站点允许通过其配置的 OAuth 提供方导入会话。
- RelayScope 不自动处理 OAuth 登录人机验证；管理员在本地完成授权，并导入最小化的会话包。
- OAuth 会话导入与 Cloudflare 恢复是两个独立的工作流，仅共享加密凭据存储。
- 偶发的勾选框式 Cloudflare 验证必须在无人值守下尝试通过。
- FlareSolverr 可以被固定版本、包装或打补丁，作为可替换的人机验证提供方。
- 若 HTTP 采集器无法复用放行 Cookie，可以在刚通过验证的浏览器会话内抓取结构化接口。
- 恢复是有边界的，会进入冷却期而不是反复请求社区站点。

## 本地优先交付

开发与验证先在 Windows 上进行。Debian 13 的生产安装属于后续交付阶段。本地工具链与缓存应放在 D 盘或 F 盘，不占用紧张的 C 盘空间。
