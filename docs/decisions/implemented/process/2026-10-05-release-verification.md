# Agent Note: 发布提交验证与构建上下文

Status: implemented

## Problem

标签发布不依赖同一提交测试成功，可能把未检查的代码标记为最新镜像。本地部署记录虽被版本控制忽略，仍会进入容器构建上下文。

## Decision

持续集成工作流可复用。发布先验证标签格式与提交属于主分支，再调用同一提交的测试、静态分析、格式检查及构建流程，成功后才授予镜像任务推送权限。前端测试使用文件集合发现，覆盖新提取模块的行为测试。

容器忽略规则额外排除生产部署记录及带后缀的环境文件，保留不含秘密的示例配置。没有修改线上权限或执行发布。

## Alternatives considered

仅查询先前检查结果可以减少执行次数，但容易误用别的提交的成功结果，也依赖检查记录存在；复用流程重新验证提供直接的同提交门禁。将测试复制到发布流程更直观，但两份检查容易随项目演进不一致。

## Consequences

标签发布多一次完整验证，耗时增加，但无法跳过测试直接发布。主分支历史上的提交仍可发布修订版本；版本选择由维护者控制。构建上下文减少敏感文件暴露，最终运行镜像仍只复制构建出的二进制。

现有模块化单体决策继续适用，本改动不引入运行时依赖。已有两篇架构/计价决定与此不冲突；本次认证、公告、前端状态决定各自负责不同边界。
