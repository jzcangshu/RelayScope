# Agent Note: 登录来源绑定、免费助力事务与会员退款权益

Status: implemented

## Problem（问题）

登录随机校验值只存在服务器内存，回调未验证发起浏览器，攻击者取得的回调可能被另一浏览器接受。免费助力先扣额度再建单，后续失败会造成余额与入账不一致。会员订单退款原来只变更订单状态，继续保留全部会员时长；直接从总到期时间扣整单天数又会误扣已消费时长或其他赠送。

## Decision（决策）

登录开始时写入十分钟、仅服务端可读的同站宽松浏览器凭据，回调以常量时间比较与查询参数中的随机值匹配后再消耗服务器记录。安全传输属性采用配置的公开回调地址，兼容代理终止加密连接的部署；会话凭据沿用同一判定。

免费助力由一个存储事务完成资格核验、月度发放、余额扣减、已支付订单创建和目标达成。事务先取得写锁再读取，任何建单或状态更新失败都完整回滚，不再静默绕过额度错误。

升级后支付的会员订单保存其贡献的开始、结束时刻。其他赠送、兑换及预登记表现为这些区间之间的时间间隙，既有延期路径无需复制新状态。退款只撤销订单区间中尚未消费的部分，并将后续订单区间等量前移，保持其他权益的时长。管理员设置较短到期日时裁剪区间，后续再次延长不会恢复已经移除的订单权益。订单状态转换及权益撤销同一事务，重放与并发只会撤销一次。

按照用户确认，历史订单不回算、不建设人工核对流程：历史总权益原样保留，无来源区间的历史会员订单在调用平台前拒绝自动退款。仅升级后支付的订单支持新语义。

平台退款使用独立持久化尝试记录，网络调用前原子抢占。明确业务拒绝允许重试；超时、断线、无明确结果的响应保留阻止重试状态，防止重复退钱。后台提供“登记已退款”入口，经管理员明确确认平台成功后，仅登记本地状态，不再次请求平台退款。即使客户端断线，也以短时后台上下文保存平台结果。免费额度订单不调用外部退款平台。

## Alternatives considered（考虑过的替代方案）

- 只验证服务器随机值：无法绑定浏览器，不能防止登录请求伪造。
- 扣额度失败后补偿：建单与补偿本身仍可能失败；采用数据库原子事务。
- 退款一律扣除整单天数：会损害已消费之后的其他续费和赠送。
- 为所有赠送来源重建完整账本：历史不足以准确重建，且需要侵入多个已可靠的延期入口。订单来源区间足以表达本次退款规则，未归属间隙保留其他权益。
- 平台报错即解除锁：网络错误不能证明资金未退，可能重复退款。

## Consequences（结果与限制）

无需新依赖。迁移新增两个独立表，兼容前身数据库报告较高版本但没有订单表的既有回归用例。多标签页同时开始登录时采用最后一次开始的浏览器凭据，较旧流程需重新开始。平台成功而本地登记失败时保留退款尝试记录，需要确认后仅登记本地状态；不会自动再次请求资金转移。后台直接修改数据库会绕过区间裁剪，管理员应使用现有会员维护入口。

验证覆盖：跨浏览器、过期及重放登录；重复订单与目标更新失败回滚；并发助力账实相符；未消费、部分消费、全部消费、并发及重复会员退款；后续续费、兑换、预登记与赠送保留；管理员缩短后延长；历史订单拒绝；平台请求抢占、明确拒绝重试及不确定结果阻断；支付响应缺少状态码、无效内容和服务异常分类。存储、登录、请求路由、支付包回归全部通过。
