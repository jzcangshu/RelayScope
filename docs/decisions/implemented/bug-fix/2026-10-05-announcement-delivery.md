# Agent Note: Announcement version delivery without replay

Status: implemented

## Problem

公告采集仅比较正文、类型、附加字段，遗漏标题；队列唯一键却只有订阅与公告编号。结果是标题更新不识别，正文更新即使识别也永远被第一次队列记录拦截。直接放开唯一键会令重复回调、原文回退或部署升级重放历史公告。

## Decision

保留公告编号。采集在同一事务中记录已见内容版本，包括静默历史回填版本；哈希使用明确分隔的字段数组，包含标题和完整正文，并规范化标题首尾空白、默认类型和附加字段。升级后的第一次采集先以数据库原有字段登记基线，再登记输入版本，旧哈希算法变化不会被当作新公告。同一首次批次中重复编号的编辑也保持静默。

第 012 号迁移在事务中重建队列表的唯一约束，完整复制每条旧记录的编号、正文、状态、次数和时间。新队列唯一键使用订阅、公告编号、完整内容版本；派发器明确传入完整哈希，不把展示站名或被截断的消息作为新版本身份。相同完整版本即使展示站名变化也不重发；新版长文第 2000 字之后的编辑也能正常入队。

旧队列以空版本标记保留。仅对这些旧行进行兼容匹配：显式传入原始公告标题，以旧消息标题是否具有对应后缀、已发送正文是否一致来兼容匹配，不猜测站名与标题的分隔位置；站名本身含分隔符也不会导致重推。这样数据库当前是 B、但历史队列曾推 A 时，升级后即使站点改名，回退 A 仍被拦截；新的标题或可见正文不会被误拦截。旧消息已被截断的长文无法恢复完整版本，当其标题和截断正文相同时保守抑制通知，以避免历史重推。这个限制只针对旧队列兼容，不影响新队列的完整内容版本判断。

每个不同的完整版本独立排队。重复待发版本不新增记录，不重置重试次数、时间或失败状态；不同版本不覆盖既有待发版本。继续使用现有重试策略，不扩大重试范围，不修改续费提醒。

## Alternatives considered

- 删除旧队列或重新生成公告编号：会破坏历史去重并重放，拒绝。
- 使用最终消息作为新版本键：长文尾部编辑被截断后无法识别，站名变化也会改变身份，拒绝。
- 旧队列只填充当前数据库的完整哈希：当前公告可能已经变为 B，旧队列实际发送 A，回退 A 时会重复，拒绝。
- 只记录最后一次内容：原文回退会再次成为新事件，拒绝。
- 覆盖原有队列行来发送编辑：会改写已发记录或重置正在重试的消息，拒绝。
- 同步重构采集与全部订阅入队为一个事务：涉及会员授权、发送渠道与采集层边界，超出这次稳定去重修复，暂不采用。

## Consequences

已见版本和队列历史会增长，以换取稳定去重。版本账本记录的是已采集，不能当作已入队或已送达凭据；采集提交后回调失败仍可能漏入队，沿用既有语义。进程在外部平台已接收消息、但本地成功状态尚未写入时崩溃，或平台接收后响应丢失，现有重试机制仍不能保证外部恰好一次。这次没有发送任何真实通知。

旧队列缺失完整长文只能保守匹配；历史标题格式本身使用站名与标题分隔符，不具备单独结构化标题字段。对于新输入无标题且正文与旧消息相同的模糊情况，保守抑制；因此旧版本仅移除标题也可能不推送，避免把含分隔符的站名误认为历史公告标题。迁移不猜测不存在的完整原文，也不修改旧消息。

验证：标题更新、长文尾部编辑、旧消息在站点改名后的回退三项回归均先确认修复前失败。存储与通知包全部测试、静态检查通过。新增测试覆盖正文/标题编辑、重复采集/回调、新版站名变化去重、原文回退、首次回填含重复编号、规范化元数据、迁移完整保留四种旧状态和时间、旧兼容不抑制真正标题/正文编辑、重试去重，以及模拟发送端完整链路。所有发送均使用内存记录器。

## Deployment compatibility follow-up (2026-10-06)

部署预演发现旧版本允许产生已经取消订阅的历史队列引用。第 012 号迁移尚未在生产执行，因此直接修正未发布迁移：队列订阅编号作为历史逻辑编号保留，不再强制引用可删除的当前订阅；复制旧记录后，仅把缺失或停用订阅的待发、重试消息标记取消，已发和失败历史不变。

取消订阅在同一事务内验证归属、取消待发/重试再删除订阅；队列读取和实际发送前均复核订阅，阻止已取出批次在取消后继续发送。入队时也要求订阅仍启用。新订阅编号取当前订阅、历史队列和投递记录中的最大编号加一，避免旧逻辑编号复用后误把历史消息关联新订阅。

回归覆盖在外键关闭时生成的旧孤儿记录、启用外键后的迁移、取消带已发和待发记录的订阅、错误所有者取消回滚、已取出消息取消后不发送、重新订阅不复活旧消息、旧投递编号不复用。旧迁移在此回归上确认报外键错误；修复后存储和通知包全部测试及静态检查通过。没有访问或修改生产数据。

发送前复核不能撤回已经发往外部平台的请求；最后一次本地核验与外部请求之间也没有跨系统原子性保证。取消后的新批次和已取出但尚未核验的消息均被阻止，不宣称可以追回在途通知。
