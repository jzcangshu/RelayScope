# Agent Note: 看板异步状态边界与响应式交互

Status: implemented

## Problem

看板在完整数据到达之前记录版本，失败后无法在同版本恢复；详情没有请求身份，旧响应可覆盖新模型。单站公告使用临时替换的全局数组，时间范围重绘丢失站点。订阅取消没有确认服务端成功。手机导航与通知面板不可见，中宽布局因固定通知栏挤压越界。

## Decision

请求与轮询状态、偏好同步、订阅传输分别位于 dashboard-state.js（看板状态模块）、preferences-sync.js（偏好同步模块）、subscriptions.js（订阅模块）。静态页面按依赖顺序加载；模块同时提供浏览器入口和直接测试入口，不引入框架或打包要求。

轮询只在完整快照应用成功后提交版本，并合并重叠请求；失败保留原卡片和原数据时间，提供重试与错误提示。详情请求使用序号与取消控制，关闭详情使旧请求失效。公告统一呈现全站列表与时间范围筛选。用户移除卡片公告入口后，单站请求、选择状态及返回全部通知控件一并去除；原单站筛选缺陷随入口取消而收敛，不保留无入口的实现。

偏好同步负责防抖和串行上传，避免较慢的旧保存覆盖新设置。账号切换或退出使未完成的读取、发送中的保存与尚未发送的队列失效，晚到的成功或错误均不能影响新账户界面。订阅模块统一检查响应，单站取消和批量取消只统计服务端已确认的结果；列表刷新失败保留原状态。

宽屏预留通知列，中窄屏改为覆盖抽屉。布局不再随开关改变最大宽度或卡片网格，工具栏依据内容容器宽度换行。抽屉限制背景焦点，支持键盘循环、退出和关闭后焦点返回；离开看板时关闭，模式计算同时检查看板可见性，避免在隐藏页面缩窄窗口后锁死导航。手机保留主导航，筛选默认折叠、显示已选数，只展示有结果或已选选项，大列表提供局部搜索。标题与卡片主体统一进入详情，公告统一通过右上角通知入口查看；遵循用户对卡片简洁度的取舍，卡片不增加公告按钮，也不改变标题行为。通知变化只显示未读提示，不再自动打开面板打断阅读。

ui-tokens.css（共享尺度样式）提供基础文字、控件高度、圆角与交互语义色，公开、定制、后台共用。遵循用户明确排除项，健康/降级状态文字色、状态徽标字号、卡片底色和粗左边框保持原值。

## Alternatives considered

直接修补原脚本能减少初次改动，但继续依赖共享异步状态，难以验证竞态；因此把三个有独立状态或传输约定的职责提取为可直接测试模块，页面保留呈现与编排。

窄屏继续使用挤压式右栏可同时看两列，但压缩卡片和控件且移动阅读位置；因此窄屏采用覆盖抽屉，宽屏保留稳定列。全量迁移框架可能改善组件组织，但与此次修复范围不匹配，也增加交付风险。

卡片内独立公告按钮能缩短单站公告路径，但用户明确认为该按钮缺乏美观与使用价值，因此保留右上角统一通知入口，避免卡片重复动作入口。

## Consequences

静态服务必须提供新增模块和共享样式。轮询错误可见但不会清空已成功加载数据。订阅操作仍遵循现有后端授权与额度约束，不发送测试通知。客户端请求序号保护呈现身份，不替代服务端事务或授权。

新增导出模块回归覆盖同版失败恢复、快照应用失败、重叠轮询、详情竞态和关闭失效、详情网络错误、订阅错误、渠道路径、偏好串行保存与退出取消。原公开页 51 项及新增 17 项测试通过。实际多宽度视觉和整页操作由主代理统一验收，模块测试不能替代浏览器布局检查。

历史决策检索：现有公告投递决策仅部分相关，负责服务端版本去重和投递语义，本篇负责客户端显示与交互，不取代该决策；其余已有决策无前端状态边界重叠。
