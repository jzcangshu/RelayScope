# 数据契约

[English](data-contract.md) | **中文**

## 身份层级

公开层级是一个查询投影，不是嵌套存储的 JSON：

```text
provider（提供商）
  monitored model rule / search label（监控模型规则 / 检索标签）
    site（站点）
      raw model（原始模型）
        site group（站点分组）
          current snapshot and time buckets（当前快照与时间桶）
```

`raw model` 与 `site group` 是来源身份。即使内部使用规范化键，它们也必须能逐字节原样展示。

项目配套的截图确认：`free group`、`translation channel`、`NVIDIA` 这类条目都是同一个原始模型下的分组。每个分组可以独立携带 TPS、首字延迟、总延迟、成功率和样本上下文。

## 通用指标字段

所有指标均可为空，除非来源明确提供了它们：

- 请求数
- 成功数
- 失败数
- 空响应数
- 成功率
- 平均延迟（毫秒）
- 首字延迟（毫秒）
- 吞吐量（token/秒）
- 采样窗口起止时间
- 来源时间桶分辨率

缺失不等于零。无法在不丢失语义的前提下表达的来源特有数据，放入一个有大小限制的 JSON 扩展字段，并带上由适配器自行管理的 schema 版本。

## 公开卡片可见性

公开卡片列表采用一种可逆的「24 小时无样本」投影。一个原始模型只有满足以下条件才有资格被隐藏：样本至少已有 24 小时历史；来源声明了至少连续 24 小时且仍然新鲜的权威覆盖区间；站点采集健康；并且当前快照与最近 24 小时的时间桶中都没有正样本或可信的无计数指标。原始模型、价格、快照与时间桶全部保留在存储中；新样本一到，卡片自动重新可见。

覆盖区间缺失或不完整属于明确的豁免情形。因此，仅存在性的健康来源（`availabilityMode=presence`）以及仅有当前值或 `skipDetails` 的站点，即使没有详细时间序列也保持可见。部分完成的详情运行只为详情请求成功的模型声明覆盖区间；失败的模型保持豁免。

## 匹配契约

存储的原始模型包含：

- 原始展示名；
- 规范化检索文本；
- 确定性分词；
- 首次与最后一次出现的时间；
- 存在/移除证据；
- 零条或多条规则匹配。

规范化仅限大小写归一与分隔符/空白归一。它不得从展示身份中去掉日期、提供商前缀、推理标记或自定义后缀。

规则支持必选词元、备选词元、排除词元、可选正则表达式、优先级、启用状态、提供商、规范名称与别名。命中解释必须被存储或可重现，使管理员预览能解释每一次命中。

## 原子性与部分进度

目录结果会标记自身是否完整。只有完整成功的目录才能累加缺席证据。详情指标可以按有边界的批次提交，让公开读者无需等待全部模型即可看到进度，但采集运行会记录自己是部分完成还是完整。

每个公开快照包含：

- 可用时的来源观测时间；
- 采集时间；
- 最近一次成功采集时间；
- 运行标识；
- 服务状态；
- 采集状态。

## 当前状态与窗口聚合

来源提供的分组摘要是窗口聚合值，不是当前观测值。它的成功率、请求数和延迟继续作为 24 小时指标可用，而分组的当前服务状态来自最新的真实序列时间桶。

最新的真实时间桶时间戳与采集时间分开存储。只要来源样本超过两小时，即使 RelayScope 刚刚抓取到一个本身有效的响应，对外也表现为 `no_samples`。这样把来源数据的新鲜度与采集器健康区分开。

公开时间线只包含已持久化的来源时间桶。空的时间线槽位绝不能插入采集时间戳或聚合状态。当来源省略时间桶结束时间时，推断出的区间上限为一小时，避免稀疏的观测点宣称未被观测到的多小时覆盖。

## 管理端投影

站点删除是可恢复的软删除：记录 `deleted_at`，停用站点，把它从调度器、公开页面和常规管理列表中排除，同时保留快照、历史、运行记录和加密会话行。恢复操作清除 `deleted_at`，站点保持禁用，直到管理员显式重新启用。历史行的过期仍由留存清理负责。

管理端的未匹配投影只包含原始模型身份、提供商提示、站点身份和最后出现时间。会话元数据只包含大小、密钥版本、用途、过期时间和更新时间；解密后的凭据、随机数（nonce）、密文、Cookie 值和访问令牌绝不会被序列化输出。

运行记录过滤在服务端有边界限制：数量上限、站点 ID、状态和 RFC3339 起始时间。非法过滤条件会被拒绝，而不是悄悄扩大查询范围。
